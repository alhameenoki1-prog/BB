Your mailbox

Emails are sent from your own address and replies are read from its inbox. Nothing is sent on anyone's behalf but yours.

Log in with your email

The quickest way in: your address and its password, and the servers are worked out for you. Gmail, Yahoo and iCloud want an app password (not your normal one): Gmail at myaccount.google.com/apppasswords after turning on 2-Step Verification. Replies are read from the same inbox.

Need to set the servers yourself? The full form is under Option {{ 'B' if gmail_available else 'A' }} below.

Fill in the servers for:

How to connect Gmail or Google Workspace (about two minutes)
  1. Click Gmail / Google Workspace above to fill in the servers.
  2. Open myaccount.google.com/security and make sure 2-Step Verification is turned on (app passwords need it).
  3. Open myaccount.google.com/apppasswords, type a name such as BB Outreach, and click Create. Google shows a 16-character password once; copy it.
  4. Below, Username is your full Gmail address and Password is that 16-character app password (spaces don't matter). Leave the IMAP fields as filled in.
  5. Click Test and save. Replies land in this same Gmail inbox, where the worker reads and answers them.

Google Workspace users: if "App passwords" is missing, your Workspace admin has turned it off (Admin console → Security → 2-Step Verification → allow users to create app passwords), or ask the admin to switch on one-click Gmail for this site.

How to connect Outlook or Microsoft 365 (sending works; reading replies needs one extra step)
  1. Click Outlook / Microsoft 365 above to fill in the servers.
  2. Work or school account (Microsoft 365): your admin must allow Authenticated SMTP on your mailbox (Microsoft 365 admin center → Users → your user → Mail → Manage email apps → tick Authenticated SMTP). Then Username is your email address and Password is your normal password (or an app password if your organisation uses multi-factor sign-in).
  3. Personal outlook.com / hotmail.com accounts: Microsoft removed password sign-in for mail apps in 2024, so these can no longer be used here. Use a Gmail, Zoho or Fastmail mailbox instead.
  4. Reading replies: Microsoft also no longer allows password sign-in over IMAP, so the worker cannot read a Microsoft inbox. To keep automatic replies, set Reply-To to a mailbox that does allow IMAP (a Gmail with an app password works) and put that mailbox's server, username and app password in the IMAP fields. Replies then arrive there and the worker reads and answers them from your Outlook address.
  5. Click Test and save. The test signs in to both servers, so it will tell you straight away if either step is missing.
Yahoo, iCloud, Zoho, Fastmail, your web host

Yahoo and iCloud need an app password too (Yahoo: Account security → Generate app password; iCloud: appleid.apple.com → Sign-In and Security → App-Specific Passwords). Zoho and Fastmail take an app password from their security settings. For a mailbox from your web host, the servers are usually mail.yourdomain.com for both SMTP (port 587 or 465) and IMAP (port 993); your host's email settings page lists them.

Option C Microsoft 365 admin app — high volume, no sign-in per user

For a Microsoft 365 tenant you administer. An app you register in Microsoft Entra sends and reads mail as one mailbox through Microsoft Graph. No app passwords, no IMAP, and no SMTP AUTH toggle. Exchange Online allows a mailbox 10,000 recipients a day and 30 messages a minute, so the Fast speed on your profile works here. Replies are read from the same mailbox.

How to register the app (admin, about five minutes)
  1. Go to entra.microsoft.com → Applications → App registrations → New registration. Name it anything (say, “BB outreach”), keep Accounts in this organizational directory only, no redirect URI. Register.
  2. On the app's Overview copy the Application (client) ID and the Directory (tenant) ID into the form below.
  3. API permissions → Add a permission → Microsoft Graph → Application permissions: tick Mail.Send and Mail.ReadWrite. Then press Grant admin consent for <your org> and confirm. Both rows must show a green tick.
  4. Certificates & secrets → New client secret. Pick an expiry (24 months is the longest), press Add, and copy the Value column right away — it is shown once.
  5. Enter the mailbox the emails come from (a real licensed user or shared mailbox in this tenant, e.g. outreach@yourcompany.com). Your profile's sending address becomes this.
  6. Optional but recommended: limit the app to that one mailbox with an application access policy, so the secret can't read any other inbox.

Personal outlook.com / hotmail.com accounts have no tenant admin and can't use this. For those, see the Outlook instructions under Option B.

What else keeps cold email out of spam
  1. Send from a domain you own, with SPF, DKIM and DMARC published (the table above). This is the single biggest factor. A free gmail.com or outlook.com address can't be fixed beyond this.
  2. Warm the mailbox up. A new address that sends 500 emails on day one gets blocked. BB ramps a fresh mailbox from 20 a day, adding 10 a day (switch off on your profile if the mailbox already has a history). Keep an eye on bounces: over a few percent and the worker stops sending on its own.
  3. Keep the first email plain. No links, no images, no HTML. BB sends the first email to each person as plain text with a links-free signature (the switch is on your profile); the full signature goes on replies and follow-ups. In segment mode it also writes three wordings of the first email and rotates them, so a hundred recipients never get one identical body.
  4. A “blocked” bounce is a spam verdict, not a bad address. “Likely unsolicited mail”, “message blocked”, “policy” or “reputation” in a bounce means the receiving side, or Google itself, judged the email as bulk. BB then pauses sending for six hours (a day after the third block), drops the follow-ups to that person and keeps the address valid. Blocks come from identical bodies sent in volume, HTML and links in first emails, a new mailbox sending too much, and a domain without SPF, DKIM and DMARC.
  5. Make it easy to opt out. Every email carries a List-Unsubscribe header that mailbox providers look for, and a plain “just reply and I'll stop” line costs nothing.
  6. Send to real addresses only. Bounces hurt more than anything. Upload lists you trust, and remove anyone who bounced before re-uploading.
  7. Volume and pace. Under 50 a day from a fresh mailbox, a few hundred from an aged one. A personal gmail.com or outlook.com address is held to the Gentle pace whatever you pick; Normal and Fast are for Workspace or Microsoft 365 on your own domain with a track record. To send more, connect more mailboxes rather than pushing one harder.
